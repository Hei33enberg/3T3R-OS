## Context

CRCP (CYMRU Robot Control Protocol) is **one schema, two transports**: IP carries it as JSON (cymru-agent skill-dispatch); radio carries it as **deterministic CBOR** inside an [RFC 0001](./0001-frame-format.md) frame with payload **Type byte `0x04`**. This RFC defines ONLY the radio wire-format and the transport-independent signing pre-image. **It never restates the Zod types** — those live in `crcp.ts`. A robot is an `cymru_agents` row with `physical.*` capability flags; there is no second registry.

The four message contracts (`CapabilityManifest`, `TaskEnvelope`, `TelemetryAck`, `EStopFrame`) and their union `CrcpMessage` are authoritative in `crcp.ts`. This document specifies how a `CrcpMessage` becomes bytes on a LoRa carrier and how its `signature` field is computed so that a message signed on the IP side verifies on the radio side and vice-versa.

## 1. Payload-type registration

Reserves **`0x04` = robot-dispatch (CRCP)** in the RFC 0001 KISS Type-byte registry. A `0x04` frame's application payload is a **CRCP payload unit** (§3). FEC follows §5 by `safety_class`.

## 2. Canonical CBOR encoding (transport-independent)

CRCP bodies are encoded with **deterministic CBOR per RFC 8949 §4.2** (core deterministic):
- definite-length items only; integers in shortest form;
- map keys sorted by bytewise lexicographic order of their deterministic encodings;
- no indefinite-length, no duplicate keys, no `NaN`/`Infinity`.

Radio-side space optimizations (logical value unchanged vs JSON):
- `signature` and `nonce` are encoded as CBOR **byte strings** (major type 2) — 64-byte raw ed25519 signature instead of 88-char base64. The IP/JSON boundary base64-encodes the same bytes.
- `agent_id` / `task_id` UUIDs MAY be encoded as 16-byte byte strings (tag 37, RFC 8949 UUID) instead of 36-char text.
- timestamps (`issued_at`/`at`) are RFC 3339 text in `crcp.ts`; on radio they MAY use CBOR epoch tag 1 (numeric). The signing pre-image (§6) fixes one canonical form so both transports agree.

## 3. CRCP payload unit (the `0x04` application payload)

```
Offset Size Field
------ ---- ------------------------------------------------------------
0      1    CRCP header byte:
              bits 7..4  CRCP major version (0x1 for v1.0)
              bit  3     FRAG flag (1 = fragmented; §4)
              bit  2     reserved (0)
              bits 1..0  type selector: 00=manifest 01=task 10=telemetry 11=estop
1..    N    if FRAG=0: deterministic CBOR of CrcpMessage.body (§2)
            if FRAG=1: 3-byte frag header (§4) then CBOR fragment
```
The 2-bit selector mirrors the `crcp.ts` `CrcpMessage` discriminated union (`type`). Receivers reconstruct the union member from the selector + decoded body and **MUST validate against `crcp.ts` before acting**.

## 4. Fragmentation

A LoRa packet payload is bounded (~200–222 B usable after RFC 0001 header + RS). If a CBOR body exceeds **`MAX_CRCP_FRAGMENT = 200` bytes**, set FRAG=1 and split:
```
frag header (3 B): msg_frag_id (u8, random/msg) · frag_index (u8, 0-based) · frag_total (u8)
```
Reassembly key = (RFC 0001 Sender ID, `msg_frag_id`). Reassembly timeout 30 s; drop incomplete sets. **`EStopFrame` MUST NOT fragment** — it must fit a single packet (it does: 16B id + 64B sig + nonce + short reason ≈ 120–140 B). Senders that cannot fit an e-stop in one packet MUST drop optional fields, never split.

## 5. Radio priority & FEC by `safety_class`

`TaskEnvelope.safety_class` (and the implicit `critical` of `EStopFrame`) maps to the RFC 0001 carrier as:

| safety_class | FEC | TDM priority | addressing | repeats |
|---|---|---|---|---|
| `routine` | RS(255,223) | normal | unicast | 1 |
| `caution` | RS(255,191) | elevated | unicast | 1 |
| `critical` / e-stop | RS(255,191) | **class 0 (preempts queue)** | **broadcast** (recipient `0xFF…`, carrier hint `0xF`) | **3× with 0–50 ms jitter** |

E-stop preempts the `cymru-radio-d` TDM queue. It remains bound by EN 300 220 duty cycle (regulatory), so it is **expedited, not unlimited** — see §7.

## 6. Signing pre-image (the load-bearing cross-CTO decision)

ed25519 covers a **transport-independent canonical pre-image** so a signature made on IP (JSON) verifies on radio (CBOR):

```
preimage = "CRCP1" (5 ASCII bytes)           ← domain/version separation
         || type_selector (1 byte: 0x00..0x03)
         || det-CBOR( body with `signature` key REMOVED )   ← RFC 8949 §4.2, §2 rules
sig      = Ed25519.sign(sk, preimage)
```
- **Encode-then-sign over canonical CBOR** (NOT over JSON, NOT over the framed bytes). Both transports compute the identical pre-image regardless of how they happen to transmit the object → one signature, two transports.
- Verify: strip `signature`, rebuild `preimage`, `Ed25519.verify(pk, preimage, sig)`.
- Public key resolution: `agent_id` → `cymru_agents` ed25519 identity. Fleet-scope `EStopFrame` (no `agent_id`) → the master/hub key bound at pairing (`hub-pairing-token` + `cymru_devices`, **not** `cross_device_sessions`).
- Domain tag `"CRCP1"` prevents cross-type / cross-version signature reuse.
- Replay protection: `TaskEnvelope` = `idempotency_key` + `issued_at`; `EStopFrame` = `nonce` + `issued_at`. Receivers keep a 5-min window + dedup table (`dispatch_lock` pattern, PK `(agent_id, idempotency_key)`).

> **`requires:cymru-input`:** cymru-agent's IP-side signer MUST sign this same canonical-CBOR pre-image (not raw JSON). Confirmed needed before either side ships signing. Posted to LINEAR-2338.

## 7. Safety model (defense-in-depth — non-negotiable)

1. **Primary fail-safe = on-robot deadman watchdog.** Every `TaskEnvelope.constraints.deadman_ms` arms an on-robot timer; loss of comms → robot safe-stops **with zero packets required**. The radio is never the sole safety path.
2. **Secondary = `EStopFrame`** — active expedited stop (§5), ed25519-verified **before** honoring.
3. **No actuator motion until the e-stop + deadman path is proven** in integration test. `validatePhysicalTask` (cymru side) rejects any `TaskEnvelope` lacking `deadman_ms`.
4. E-stop is expedited but duty-cycle-bound; never rely on radio delivery for safety — that is the watchdog's job.
